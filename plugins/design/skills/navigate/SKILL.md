# レポートナビゲーション

**どのレポートを書けばよいか分からないとき、最初に実行するスキルです。**

文書は作りません。**相談**（やりたいことを自然文で受け取り、必要なレポートと順序を提示）と
**診断**（既存の `docs/design/<slug>/` の不足・食い違いを指摘）の 2 つだけです。
引数（`$ARGUMENTS`）があれば相談、無ければ診断から入ります。両方やることもあります。

## 1. 状況を掴む

**ユーザーに聞く前に調べます。**`docs/design/` の既存案件（あれば `00-index.md` を読む）、
ソースコードと git 履歴の有無（`新規` か `機能追加` かの推定材料）、現在のブランチ名。

## 2. 意図を分類する

引数を [INTENT-MAP.md](INTENT-MAP.md) の対応表に当てはめ、**暫定の推奨セット**を作ります。
この時点で答えは出ています。以降の質問は、それを削るか足すかの微調整です。

## 3. 最小セットを確認する

**その機能を過不足なく説明するには、4 つの問いに答えれば足ります。**

| 問い | 答えるレポート | 無いと起きること |
| --- | --- | --- |
| 何を作るのか | `02-requirements-analysis` | 完了判定ができない |
| どう作るのか | `05-architecture-design` | 実装者が毎回設計し直す |
| 何が壊れるのか | `07-impact-analysis` | リリースで事故る |
| どう確かめるのか | `11-test-plan` | 「動いた」の基準が人によって違う |

`新規` なら **02・05・11**、`機能追加` なら **02・07・11** が最小セット。ここは削りません。

## 4. 絞り込み質問（収束型）

最小セットに何を上乗せするかを、[INTENT-MAP.md](INTENT-MAP.md) の「追加条件」表から詰めます。
**判断がつかない項目だけ**聞きます。環境から分かること、答えても推奨が変わらないことは聞きません。

進め方は次のとおりです。**この形を崩さないでください。**

1. **質問の前に、現時点の推奨を出す。**「現時点の推奨：`02`・`07`・`11`」
2. **1 問ずつ、推奨案を添えて聞く。**「はい／いいえ」で答えられる形に
3. **答えるたびに推奨を更新して見せる。**増減の理由を一行添える
4. **毎回「ここで確定してよいですか」を添える。**いつでも打ち切れるようにします
5. **上限 6 問。**分類が明確なら **0 問で確定してかまいません**。
   超える分は無理に決めず、**その判断が要るレポートを「任意」として提示**し、
   実行する工程側で聞いてもらいます

このスキルは grill-me とは違い、**結論を保留しません。**推奨は最初から手元にあり、
質問はそれを鋭くするだけです。途中で止めても使える答えが残ります。

### 聞いてはいけないこと

要件そのもの（利用者は誰か、どんな画面か、何を保存するか）は聞きません。
**それは `/design:02-requirements-analysis` の仕事です。**ここで聞くと、
02 で同じことをもう一度聞かれることになります。

このスキルが聞いてよいのは「**どのレポートが要るかを左右する事実**」だけです。

## 5. 既存文書を診断する（案件ディレクトリがある場合）

| 確認 | 見るもの |
| --- | --- |
| 未作成 | `00-index.md` の工程一覧で `完了` でないもの |
| 縦串の断絶 | `02` の `受入基準` が `10` `11` で全件対応しているか |
| 用語の揺れ | `02` の `用語定義` に無い語が下流文書で使われていないか |
| 拾われていない宿題 | `03` `06` `07` `08` の未解決事項が `09` に登録されているか |
| 陳腐化 | 更新日が他より明らかに古く、内容が食い違っているもの |

## 6. 提示する

- **いま置かれている状況** — 調べて分かった事実。1〜3 行
- **推奨するレポートと順序** — 表：`# / コマンド / 何のために / 必須か任意か`
- **今すぐ実行するコマンド** — **1 つだけ。**迷わせません
- **今回は書かなくてよいもの** — 理由を添えて。**書かない判断も提示します**
- **診断結果**（既存文書がある場合） — 足りないもの、食い違っているもの

## ルール

- **本スキルは文書を作成しません。**案内と診断だけです
- **全工程を勧めないでください。**17 個すべて必要な案件はほぼありません。
  削る提案ができないナビゲーションは役に立ちません
- 迷ったら**少なく勧めます。**足りなければ後から追加できますが、書きすぎた文書は誰も更新しません

## 次の工程

このスキル自体が「次の工程」を決めるためのものです。手順 6 で提示した
**「今すぐ実行するコマンド」がそのまま次の一手**になります。
