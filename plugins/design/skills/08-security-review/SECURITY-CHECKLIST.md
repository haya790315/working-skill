# セキュリティレビュー観点チェックリスト

**全項目に目を通してください。**該当しない項目は「対象外」と理由を記録します。
「見ていない」と「見て対象外と判断した」は別物です。

## 認証

- 認証方式は社内標準・既存システムと整合しているか
- パスワード・秘密情報の保存方式（ハッシュ、ソルト、鍵管理）
- 多要素認証の要否と、その判断根拠
- セッションの有効期限、固定化対策、ログアウト時の破棄
- ログイン試行回数の制限、アカウントロックの方針
- パスワードリセット経路が認証を迂回する抜け道になっていないか

## 認可（アクセス制御）

- 権限モデルが既存の方針と食い違っていないか
- **画面を隠すだけでなく、API 側でも権限を検証しているか**
- 他人の ID を指定すると他人のデータが見える構造になっていないか
- 管理者機能への到達経路と、その保護
- 権限昇格につながる操作の有無

## 入力値の扱い

- 外部からの入力を信頼していないか（クライアント検証だけで済ませていないか）
- SQL、コマンド、テンプレート、LDAP などへの注入対策
- ファイルアップロードの種別・サイズ・保存先・実行可能性
- パス指定を含む入力によるディレクトリ横断の可能性
- 外部 URL を受け取って通信する処理（内部ネットワークへの到達）

## 出力の扱い

- 画面出力時のエスケープ
- エラーメッセージに内部情報（スタックトレース、SQL、パス）が出ていないか
- レスポンスに必要以上のフィールドが含まれていないか

## データ保護

- 個人情報・機微情報の特定と、保存場所の把握
- 通信の暗号化、保存時の暗号化の要否
- 鍵・認証情報の管理方法（**ソースコードや設定ファイルへの直書きが無いか**）
- 保持期間と削除の仕組み
- バックアップとその保護
- 検証環境に本番データを持ち込んでいないか

## ログと監査

- 誰が何をしたかを後から追えるか
- **ログに秘密情報・個人情報が出ていないか**
- ログの改ざん防止と保持期間
- 監査要件（社内規定・法令）を満たしているか

## 外部連携

- 連携先の認証方式と資格情報の管理
- 連携先から受け取るデータの検証
- 連携先障害時の挙動（情報が漏れる、権限が緩む方向に倒れていないか）
- Webhook など外部から呼ばれる口の署名検証

## 依存関係とインフラ

- 依存ライブラリの既知脆弱性と更新方針
- 公開範囲（本来内部のはずの口が外部公開されていないか）
- 管理コンソール・デバッグ機能の本番での無効化
- 既定の認証情報・サンプル設定が残っていないか

## 運用

- 障害時・調査時の本番データへのアクセス手順と記録
- 退職・異動時の権限剥奪
- インシデント発生時の連絡・報告経路

## 規定・法令

- 社内セキュリティ規定への適合
- 個人情報保護に関する要件
- 業界固有の規制（該当する場合）
- 委託先・再委託先がある場合の管理責任
