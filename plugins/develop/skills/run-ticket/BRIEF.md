# 開工整理的輸出格式

給使用者在對話中看，用**中文**。要**詳細**：讀完就能動手，不用回頭再翻票和 code。
每一節都寫具體內容，例如畫面上看到什麼、哪個 API 回傳什麼、在哪個檔案；不要寫成空泛的摘要。
沒有內容的節寫「無」，不要整節刪掉，讓使用者知道這節確認過了。

```
## TUMIKI-203 【A-6】メンバーと部署の画面：部署ごとの人数と人ごとの所属
<票的網址>

### 一句話
這張票做完之後，什麼會變成怎樣。

### 背景：為什麼要做
- 這個功能／畫面是做什麼用的、誰在用
- 為什麼現在要做：源自哪張父票、哪個專案目標、哪個客戶需求、哪個事故（附出處）
- 在整體中的位置：父票的目標、兄弟票各自負責什麼、這張票卡住誰、被誰卡住

### 目前的問題
逐項寫「現在實際的行為」與「為什麼是問題」，並附確認的位置。
- 左邊的部署列表，沒選中的部署人數顯示「—」
  原因：orgUnits.tree 的 memberCount 固定回 null（src/server/.../org-units.ts）
  影響：管理者看不出各部署有多少人
- …

### 需要改善的點
把問題轉成「要做到什麼」，用使用者或呼叫端看得到的行為描述，並標出票上寫的完成條件。
- [ ] 所有部署都顯示人數（含底下的課，同一人只算一次）
- [ ] …
完成條件：票上有就照抄，沒有就寫「票上未定義」，並提出建議的完成條件。

### 修改方向
- 建議做法：要動哪幾塊、大致怎麼改（1 段到數段，可以提到檔案和 API）
- 影響範圍：會連帶影響的畫面、API、其他票
- 風險與注意：效能、資料量、權限、相容性
- 有多種做法時，列出選項和取捨，並寫出推薦哪一個

### 票上已過期
- 票寫「control-plane.ts:1818」→ 現在在 :1902
- 票寫「users.list 不回傳所屬」→ 已在 PR #〇〇 修好

### 不清楚、要問人的
- 誰能決定什麼：〜（建議問○○，依據是票的建立者或負責人）
```

## 寫法要點

- **目前的問題**是重點：一定要到 main 上實際確認，不能只把票上的文字換句話說。
- 推測寫成「推測：〜（依據：〜）」。
- 票本身寫得很詳細時，不要重複抄一遍；改成補充票上沒寫的部分（背景、影響範圍、過期資訊）。
