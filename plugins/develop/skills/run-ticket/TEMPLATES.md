# 寫回區塊的範本

區塊從 `<h3>対応内容（YYYY-MM-DD）</h3>` 開始，順序是：`PR` → `対応方針` → 主體寫法（依票的類型選）→ 其餘固定段落。
**整個區塊約 20 行以內。**
以下用日文票為例；原票是其他語言時，標題也跟著換。

## 選主體寫法

| 票的類型 | 判斷依據 | 主體寫法 |
| --- | --- | --- |
| 功能、修 bug、改 UI | 使用者或呼叫端看得到的行為改變了 | Before → After |
| 調查、驗證 | 產出是「知道了什麼」，不是程式碼 | 結論／確認したこと／確認できなかったこと |
| 做決定、定規格 | 標題有「決める」「仕様未定」「〜するか」 | 決定／理由／採らなかった案 |
| 重構、內部改動 | 外部行為不應改變 | 変わったこと／変わらないこと |

同時符合多種時，以**同事最想知道的那件事**為主體，其他放進固定段落。

## 主體寫法

**Before → After**（一項一行，開頭寫項目名稱）
```
部署の人数　Before：選んでいる部署だけ。ほかは「—」 → After：すべての部署に人数。配下の課も含め、同じ人は1回だけ数える
```

**調査・検証**
```
結論：〜は期待どおり動く。ただし〜の場合だけ例外がある
確認したこと：〜（根拠：手順、ログ、環境）
確認できなかったこと：〜（理由）
```

**決定**
```
決定：〜にする
理由：〜
採らなかった案：〜（採らなかった理由を一行で）
```

**リファクタ**
```
変わったこと：〜
変わらないこと：画面・API の挙動は同じ。〜のテストで確認
```

## 固定段落（內容是空的就整段省略）

```
PR: #2299

対応方針（必寫，1～3 行：怎麼處理的）
・名簿を1回で取り、部署ごとの人数と所属は画面側で組む形に変えた

仕組み（做法不直觀時才寫，3～5 行）
・名簿は members.roster で1回だけ取る → 画面側で部署ごとに数える
・配下の課の人は internal-manager 側で組む（Keycloak は直属しか返さない）

補足（他の人向け）
・users.list は groupMemberships を返さなくなった。所属が要るときは members.roster
・前提は1人1部署

未対応・要検討
・名前が「名 姓」の順で出る。control plane の組み方が原因 → 【A-6a】TUMIKI-228
・複数部署の人は一覧で1つだけ。どれを主にするか要決定（担当：PM）
```

`未対応` 每項的格式：**現象．為什麼沒做 → 下一步**（票號，或「誰要決定什麼」）。
